## 1. 背景与目标

在已确认的 MVP 范围内，准备从空仓库搭建可在 iPad 上使用的 Phoebe's Room：二年级数学 + 英语，做题+解析，题库+AI 相似题，三类练习入口。

**本计划在获得你的明确许可前不执行代码实现。**

## 2. 已确认结论

- 家庭自用；小学二年级；数学 + 英语
- 场景：课后巩固、薄弱专项、日常习惯；主设备 iPad；目标 App Store
- 题库为主 + AI 相似题生成与检查；知识点组织；不绑教材
- 做题为主 + 解析；人设「爸爸 & 朋友」
- 云端模型 API；无指定技术栈

## 3. 建议技术栈（待你确认）

| 层 | 建议 | 理由 |
|----|------|------|
| 客户端 | **Expo（React Native）+ TypeScript** | iPad 布局友好，TestFlight/App Store 路径成熟，迭代快 |
| 导航/UI | Expo Router + 自研儿童友好组件 | 触控大、少干扰 |
| 后端 | **Node.js（或 Python FastAPI）轻量 API** | 题库/进度/鉴权；**LLM Key 仅存服务端** |
| 数据 | PostgreSQL 或 SQLite 起步（单家庭可先简单存储） | 知识点、题目、作答、掌握度 |
| AI | 云端 LLM API（供应商待定） | 相似题生成、解析润色 |
| 秘钥 | 环境变量 / 密钥管理，禁止打进 App | App Store 与安全基本要求 |

备选：若你坚持原生体验优先，可改为 **SwiftUI**；计划中的模块边界不变，仅客户端技术替换。

## 5. 实现步骤（许可后）

### Phase A — 工程骨架

1. 初始化 Expo 应用（平板方向优先）与后端骨架
2. 打通「健康检查 + 拉取知识点列表」
3. 单家庭本地/简单账号方案（可先无复杂登录）

### Phase B — 内容与做题闭环（建议先数学或英语一门跑通）

1. 导入知识点 + 种子题
2. 练习会话：抽题 → 作答 → 批改 → 展示解析
3. 接入「爸爸 & 朋友」解析语气（模板 + LLM 润色可选开关）

### Phase C — AI 相似题管道

1. 基于种子题的生成 Prompt 与结构化输出
2. 自动检查器（格式、答案可验证性、知识点标签、敏感词/年龄）
3. 通过后入题池；失败入驳回日志

### Phase D — 三入口 + 掌握度

1. 课后巩固 / 薄弱专项 / 日常习惯路由与选题策略
2. 掌握度累计与简单展示
3. 双学科切换（数学 / 英语）

### Phase E — 上架准备（可并行靠后）

1. TestFlight 构建
2. 隐私政策、儿童数据披露材料
3. 按你的决定推进 App Store 审核

## 6. 风险与回滚

| 风险 | 缓解 |
|------|------|
| AI 生成题错误（尤其数学） | 种子题锚定 + 自动验算/选项一致性检查；高风险题人工抽检 |
| App Store 儿童类合规 | 尽早读审指南；默认无行为广告；数据最小化 |
| 二年级英语若含听力增加复杂度 | MVP 可先纯视觉题型（待你确认） |
| 技术栈事后更换成本 | 先冻结 Expo 或 SwiftUI 二选一再开工 |

回滚：文档与内容种子可独立保留；客户端/后端按模块提交，便于弃用错误方向分支。

## 7. 验收标准（开发完成后按工作流第六步执行）

- 功能：二年级数学、英语均可完成至少一条「选题→作答→解析」路径
- 三入口可进入练习（策略可简单）
- 相似题生成有检查日志；不合格题不可直接练
- iPad 竖/横至少一种主布局可用且儿童可读
- 双视角验收报告（前端设计 + 视觉交互）并请你确认是否返工

## 2. 我方复述（请确认）

请确认以下理解是否正确；有偏差请直接改写。

1. **产品本质**：面向儿童/青少年的 **AI 陪练式知识点强化训练**，不是完整网课平台。

3. **核心价值**：围绕知识点做「诊断 → 练习 → 反馈/讲解 → 复盘 → 再测」闭环，并积累掌握度。

## 3. 疑问清单（请逐条回复或批注）

### A. 用户与使用场景

1. **首要学习者画像**：是否就是家庭自用（例如特定孩子），还是希望做成可给更多家庭使用的产品？
2. **启动学段**：第一期更想先做小学、初中还是高中？有没有「先攻一个年级 + 一两门课」的偏好？
3. **家长角色**：家长需要「只看报告」、还是「能布置任务 / 限时 / 审阅错题」？深度希望到哪一层？
4. **使用场景**：更偏课后巩固、考前突击、日常习惯打卡，还是薄弱点专项突破？可多选并排序。
5. **设备**：主要在电脑浏览器、平板，还是手机？有没有必须支持的端？

### B. 学科与内容

6. **首期学科**：数学 / 语文 / 英语 / 理科综合 / 其他？建议先定 1～2 门把闭环跑通。
7. **教材与考纲**：是否需要绑定具体教材版本（人教版等）或地区考纲？还是以「知识点通识」为主？
8. **内容来源策略**：更倾向「精选题库 + 人工」还是「AI 生成 + 审核护栏」还是混合？对「正确性」的底线是什么（尤其数学步骤、语文标准答案争议题）？
9. **题型范围**：选择、填空、解答、口语、作文批改……首期要包含哪些？

### C. AI 形态与安全

10. **AI 人设**：更像严厉教练、温和学长，还是可切换？是否要固定角色 IP（与 “Room” 世界观相关）？
11. **交互形态**：以「做题为主、讲解为辅」，还是「对话式教学为主、题目穿插」？
12. **安全边界**：是否禁止闲聊？是否需要家长密码墙、每日时长上限、敏感内容过滤的硬性要求？
13. **语言**：界面与讲解默认中文？是否需要中英双语（英语学科场景）？

### D. 进度与 pedago（教学法）

14. **掌握度**：你更认可用「星级 / 百分比 / 熟练档」中的哪类表达？是否需要可解释（例如「近 7 次正确率」）？
15. **间隔复习**：首期是否必须有遗忘曲线式复习计划，还是 MVP 只做「错题本 + 手动再练」？
16. **激励设计**：要不要积分徽章？若要，如何避免成瘾感（我建议默认克制）？

### E. 技术与交付偏好

17. **技术栈偏好**：是否有既定偏好（如 Next.js / Python / 本地优先等）？还是希望我根据场景给建议后再定？
18. **模型与 API**：是否已有可用的 LLM / 多模态 API Key 与供应商偏好？是否需要支持本地模型？
19. **部署**：仅本地演示、家庭内网，还是公网小流量试用？
20. **隐私**：数据能否出域调用云端模型？儿童学习记录的存储位置有无硬性要求？

### F. 文档与协作（本次已部分落地）

## 4. 建议（供讨论，非正式决策）

### 4.1 产品策略

- **垂直打穿再扩展**：MVP 建议「1 个学段 × 1～2 个学科 × 完整训练闭环」，再横向加学科、纵向加学段。
- **知识图谱先行一点点**：即使内容很少，也要有稳定的知识点 ID 与前置关系，否则跨年复用会推倒重来。
- **AI 定位**：做「出题 + 批改讲解 + 激励文案」的陪练，而不是百科老师；高风险题型（作文、开放题）可二期再上。

### 4.2 体验与安全

- 儿童主界面与家长界面分离；家长能力默认「只读报告 + 时长提醒」。
- 激励以「掌握进步」为主，弱化排行榜与强制连续打卡。
- 所有 AI 输出经过学科+年龄护栏策略（后续写入技术规范）。

### 4.3 文档与节奏

- 你回复本清单后，进入：**更新 BACKGROUND / PRD → 若范围够大则写 `2026XXXX_plan.md` → 等你明确许可再开发**。
- 未确认项保持「待确认」，不假装已定。

### 4.4 命名与世界观（可选）

- 「Room」可做成温和的学习空间隐喻（书桌、书架、练习角），但首期不必过度游戏化。是否强化 IP/世界观请你定。
